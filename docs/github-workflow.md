# GitHub Workflow

## 기본 원칙

- 기능 하나당 Issue 하나를 만든다.
- Issue 하나당 Pull Request 하나를 만든다.
- Pull Request에는 변경 목적, 작업 내용, 확인 방법을 적는다.
- `main` 브랜치는 항상 실행 가능한 상태로 유지한다.

## 브랜치 이름 예시

- `init/project-setup`
- `feature/create-todo`
- `feature/edit-todo`
- `feature/delete-todo`
- `feature/toggle-complete`
- `feature/category-management`
- `feature/local-storage`
- `test/todo-flows`

## 커밋 메시지 예시

- `init: scaffold todo scheduler project`
- `feat: add todo model`
- `feat: render todo list`
- `feat: add create todo form`
- `fix: keep completed todos visible`
- `test: cover todo status changes`
